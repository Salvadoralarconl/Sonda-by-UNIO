# Approved Phase 5 Admin provisioning amendment

Approved 2026-09-24. Supersedes the original Phase 5 exclusion of all application/Profile/source provisioning. All other approved boundaries remain unchanged.

Admin may create an Application (name and optional description), create its initial editable Profile Draft, and create/configure a narrowly scoped Log Source. Team and actor come from current authenticated membership. No publication, activation, session registration or file reading occurs during these commands. The initial draft has no application-specific phrases; validation may require the Admin to complete its rules.

Every mutation carries a nonempty operation ID. The same actor/team/action/normalized request replays its committed result; reuse with different content fails. Applicable draft/source revisions prevent lost updates. Resource IDs are generated by the server. Creation and its receipt/audit commit together. Foreign parent IDs return the same missing-resource response as unknown IDs.

Paths are manually supplied, fully qualified local or UNC paths. Server configuration owns the explicit allowed monitoring roots (including UNC server/share authority). No HTTP operation creates an allowed root. Reject device paths, drive-relative paths, traversal, alternate data streams, ambiguous Windows names, and paths outside a root. Validate auxiliary producer/rotation manifest paths as well. No mapped drives, supplied credentials, file browsing, existence probing or arbitrary reads. Syntactically valid allowed UNC configuration is not evidence of SMB capability. Existing Phase 4 read-time containment and identity checks remain authoritative.

Persist inactive source configuration until the exact Profile completes validation, simulation, publication and explicit activation. Desired enabled state does not bypass that gate. Initial monitoring registration must be recoverable and idempotent without calling the publish-and-activate harness helper. Existing monitored source changes must use the accepted fenced/drained source-change boundary; no checkpoint/generation/gap manipulation or source repair is exposed.

Additional acceptance cases: Admin creates Application/Profile/Source; Member is denied; cross-team parents cannot be used; duplicate operation replays; conflicting reuse fails; outside-root path fails; valid local root passes; allowed UNC configuration passes without SMB reads; draft remains inactive; historical versions/runs/incidents remain unchanged. Include concurrent duplicates, expected-revision conflicts and COMMIT acknowledgment loss.

No frontend, Canva changes, collectors, arbitrary repair/control, notifications, deployment or real GiroSol access. Preserve all 309 existing tests and the 237 original subset. The five Phase 4 environmental gates remain pending.
