Application and Order outcomes remain independent of diagnostics and workflow. Same-cycle retries create linked attempts. Exact Problem Identity groups repeated failures into occurrences; recurrence after resolution creates a new episode. A causally later eligible success can resolve or confirm an episode without rewriting failed occurrences or a manual resolution. Expected duration/grace can indicate overdue; only configured fallback plus an explicit complete frontier finalizes missing outcomes. Compatible activation pins open parents and children to their original version; newly begun cycles use the active version.

## Reproduction and limits

Use the pinned local SDK/package environment from Phase 2. Set `SONDA_TEST_ADMIN` privately to a disposable PostgreSQL18 administrator connection, then run `dotnet test Sonda.sln -c Release --no-restore`. Integration tests fail if the database is missing; they do not mock EF or silently skip. The fixture creates isolated databases/limited roles and removes them afterward. Run the simulator with `--input artifacts/phase3/fixtures/same-cycle-retry/request.json --output <local-directory>`.

- Scope remains deterministic simulation and durable command processing. No production reader, scheduler, accounts/HTTP API, frontend, notification system or deployment exists.
- Frontiers and source observations are explicit trusted harness inputs. A later monitor must establish real source completeness before issuing a clock command; this phase does not infer file-reader progress.
- Reconstruction loads bounded session history. No production throughput/retention guarantee is claimed. No distributed infrastructure was added.
- Workflow actors are audited strings, not authenticated identities. Authentication/authorization must precede exposing these commands to users.
- Blocked ambiguous partitions retain their rejection across restart. Corrected-profile reprocessing/unquarantine is a separate future feature; finalized outcomes are not silently rewritten.
- LegacyV1→revision2 requires a drained lane; compatible revision2 activation supports open runs. Revision2→LegacyV1 downgrade is rejected. Parsing, correlation or routing changes requiring a different route must drain first.
- Publication retains the Phase 2 line-simulation entry point; rich scripted workflow reports are provided by the command simulator. A future configuration UI must define required sample coverage rather than treating an empty valid sample as proof of production log compatibility.
- Actual database commit timestamps can be absent when PostgreSQL tracking is disabled; processing and acknowledgment times never substitute for them. Synthetic completion uses an explicit effective deadline kind and has no raw source timestamp.
